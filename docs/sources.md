# Forecast sources

Each source has its own subsection under `[Forecast]`.  Options common to all of
them — `interval`, `max_age` — are described in
[Configuration](configuration.md#options-every-source-shares); this page covers
what is particular to each.

The seven downloading sources also accept `url` (to override the service
endpoint) and `max_tries` (default `3`, how many times to retry a download).
You should rarely need either.  A `url` you set is treated as a base: the API
key, location and other download parameters are appended to it, which is what
you want when a service simply moves its endpoint.  If your `url` already
carries a query string, it is used exactly as written and nothing is added —
that is the escape hatch for hand-building a request.

Two sources differ.  NWS's endpoint always carries a query string, so the
forecast office (`issuedby=`, from your `foid`) is still appended unless your
`url` already names one.  Pirate Weather (DS) carries the key and location in
the path rather than the query string, so a DS `url` that already holds your
API key is used exactly as written.

Zambretti and XTide read neither — they generate rather than download, so
setting those under `[[Zambretti]]` or `[[XTide]]` does nothing.

## No account required

### NWS

US National Weather Service point forecasts, parsed from the Point Forecast
Matrix.  US locations only, and no API key.

```
[Forecast]
    [[NWS]]
        # National Weather Service location identifier
        lid = MAZ005

        # National Weather Service forecast office identifier
        foid = BOX

        # Disambiguates when a lid appears more than once in the document.
        #lid_desc = Lowell-Middlesex MA
```

| Option | Default | |
|:-------|:--------|:--|
| `lid` | *required* | Location identifier |
| `foid` | *required* | Three-letter forecast office identifier |
| `lid_desc` | none | Used only when a `lid` is repeated in the document |
| `interval` | `10800` | 3 hours |

To find yours, look up your forecast office identifier, then request a point
forecast in a browser:

```
https://forecast.weather.gov/product.php?site=NWS&product=PFM&format=txt&issuedby=YOUR_THREE_LETTER_FOID
```

Scan the output for the location identifier matching your location.  There is a
lookup at <https://hads.ncep.noaa.gov/USGS/>.

{: .note }
> Some forecast documents list the same `lid` twice.  If yours does and the
> first entry is not the one you want, examine the document, find the
> description of the entry you do want, and set `lid_desc` to it.  Otherwise
> leave `lid_desc` out entirely.

### Zambretti

A forecast computed on your own machine from your barometer's pressure trend,
using the Zambretti algorithm.  No network access, no account, and no location:
it forecasts for wherever your station is.

```
[Forecast]
    [[Zambretti]]
        # NORTH or SOUTH
        #hemisphere = NORTH
```

| Option | Default | |
|:-------|:--------|:--|
| `hemisphere` | `NORTH` | Set `SOUTH` for a southern hemisphere station |
| `interval` | `600` | 10 minutes |
| `winddir_period` | `1800` | Seconds used to average wind direction |
| `pressure_period` | `10800` | Seconds used to determine the pressure trend |
| `lower_pressure` | `950.0` | Bottom of the calibration range, millibars (hPa) |
| `upper_pressure` | `1050.0` | Top of the calibration range, millibars (hPa) |

The `barometer` reading is used, not station pressure.  `lower_pressure` and
`upper_pressure` calibrate the forecaster to your climate; the defaults suit most
locations.

The result is a code from `A` to `Z` with a description — see
[template tags](tags.md#zambretti) and [labels](skins.md#zambretti-codes).

### XTide

Tide predictions, generated by running the `xtide` `tide` program locally.
Requires xtide and its harmonics data — see
[Installation](installation.md#building-and-installing-xtide).

```
[Forecast]
    [[XTide]]
        location = Palo Alto Yacht Harbor, San Francisco Bay, California
        prog = /usr/local/bin/tide
```

| Option | Default | |
|:-------|:--------|:--|
| `location` | *required* | A station name xtide knows.  List them with `tide -ml` |
| `prog` | `/usr/bin/tide` | Path to the `tide` program |
| `interval` | `1209600` | 14 days |
| `duration` | twice `interval` | How far ahead to predict, in seconds |
| `max_age` | `2419200` | 28 days |

Station names usually contain commas; that is expected and handled.  Copy the
name exactly as `tide -ml` prints it.

{: .note }
> The harmonics data packaged for Debian and Raspberry Pi OS (`xtide-data`)
> covers US waters and a handful of western Pacific stations, and nothing in
> Europe: most European countries restrict their hydrographic data, so it
> cannot be redistributed with xtide.  If `tide -ml` does not list a station
> near you, XTide has no data for your coast rather than a fault — you will
> need a harmonics file covering it before this source can do anything.

{: .important }
> Tide forecasts require Python 3.7 or later.  On an older Python this source
> logs that requirement at startup and declines to run, leaving the other
> sources unaffected.  UKMO has the same requirement.

## API key required

These sources need an account.  weewx-forecast supports only the no-cost service
level of each.

### WU

Weather Underground.  Obtain an API key at
<http://www.wunderground.com/weather/api/>.

```
[Forecast]
    [[WU]]
        api_key = XXXXXXXXXXXXXXXX
```

| Option | Default | |
|:-------|:--------|:--|
| `api_key` | *required* | |
| `geocode` | none | `"33.74,-84.39"` |
| `iataCode` | none | Airport code, e.g. `DEN` |
| `icaoCode` | none | e.g. `KDEN` |
| `placeid` | none | Weather Underground place id |
| `postalKey` | none | e.g. `81657:US` |

If none of the five location options is given, your station's latitude and
longitude are used.  If more than one is given, the first in the order listed
above wins.

### OWM

OpenWeatherMap.  Obtain an API key at <http://openweathermap.org/appid>.

```
[Forecast]
    [[OWM]]
        api_key = XXXXXXXXXXXXXXXX
```

| Option | Default | |
|:-------|:--------|:--|
| `api_key` | *required* | |
| `location` | station lat/long | |
| `forecast_type` | `5day3hour` | |

### UKMO

UK Met Office Global Spot, three-hourly.  Obtain a key from the Met Office
DataHub at <https://www.metoffice.gov.uk/services/data/met-office-weather-datahub>.
It must be a key from the newer DataHub service, not the retired DataPoint.

```
[Forecast]
    [[UKMO]]
        api_key = XXXXXXXXXXXXXXXX
        #latitude = 51.5081
        #longitude = -0.0759
```

| Option | Default | |
|:-------|:--------|:--|
| `api_key` | *required* | |
| `latitude` | station latitude | |
| `longitude` | station longitude | |

{: .note }
> UKMO is the one source keyed by coordinates rather than a location name.  The
> options are `latitude` and `longitude` — spelled exactly that way.

{: .important }
> UKMO forecasts require Python 3.7 or later, the same as tides: its parser
> calls `datetime.fromisoformat`.  On an older Python this source logs that
> requirement at startup and declines to run.

### Aeris

Aeris Weather.  Obtain a client id and client secret at
<http://www.aerisweather.com/account>.

```
[Forecast]
    [[Aeris]]
        client_id = XXXXXXXXXXXXXXXX
        client_secret = XXXXXXXXXXXXXXXX
```

| Option | Default | |
|:-------|:--------|:--|
| `client_id` | *required* | |
| `client_secret` | *required* | |
| `location` | station lat/long | ZIP, `city,state`, `lat,long`, ICAO, IATA, `fips:53033`, NOAA zone |
| `forecast_type` | `1hr` | 1, 3, 6, 12 or 24 hour increments |

### WWO

World Weather Online.  Register at
<https://www.worldweatheronline.com/weather-api/>.

{: .note }
> World Weather Online retired its old `free/v2` endpoint, which now answers
> every request with 403.  The default `url` is the `premium/v1` endpoint,
> which accepts the key from a free WWO account as well as a paid one.

```
[Forecast]
    [[WWO]]
        api_key = XXXXXXXXXXXXXXXX
```

| Option | Default | |
|:-------|:--------|:--|
| `api_key` | *required* | |
| `location` | station lat/long | US ZIP, UK post code, Canadian postal code, IP address, `lat,long`, or city name |
| `forecast_type` | `3` | 3, 6, 12 or 24 hour increments |

### DS

Pirate Weather — the drop-in replacement for the shut-down Dark Sky service.
The source is still named `DS` for compatibility.  Obtain an API key at
<https://pirate-weather.apiable.io/>.

```
[Forecast]
    [[DS]]
        api_key = XXXXXXXXXXXXXXXX
        #forecast_type = daily
```

| Option | Default | |
|:-------|:--------|:--|
| `api_key` | *required* | |
| `location` | station lat/long | `latitude, longitude` |
| `forecast_type` | `daily` | `daily` or `hourly` |
| `extend_hourly` | `False` | Extends an `hourly` forecast from 2 days to 7 |
| `language` | `en` | |
| `use_compression` | `True` | Request a compressed response |

`extend_hourly` applies only when `forecast_type` is `hourly`.
